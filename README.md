# Антракт

Планер актёра для съёмок, репетиций, спектаклей и личных дел. Интерфейс работает на телефонах и компьютерах. Календарь можно открыть без аккаунта. Для личных записей нужен вход.

[Открыть планер на GitHub Pages](https://arishkawolf.github.io/planer/).

## Как пользоваться

- Выбери вид «День», «Неделя», «Месяц» или «Год». Нажатие на заголовок периода открывает выбор даты.
- Добавь событие кнопкой «Событие» или напиши помощнику «Съёмка 10 ноября», «Репетиция завтра в 14:30» или «Кастинг 15.11.2026 в 12». Дату без года помощник ищет начиная с сегодняшнего дня.
- Спроси «Когда у меня съёмка?», «Что у меня завтра?» или «Когда у меня выходной?». Свободным считается день без личных событий и показов из афиши. Если за этот месяц нет опубликованной афиши, помощник это отметит.
- Чтобы изменить или удалить свою запись, нажми на неё в списке дел дня. Показы из афиши открывают карточку со ссылкой на сайт театра.
- Планер и афиша используют московские даты. Открытая переписка сбрасывается при выходе и перезагрузке, добавленные через неё события сохраняются.

## Локальный запуск

Запусти из каталога проекта `python -m http.server 8765` и открой [планер](http://localhost:8765/). Сборка и сторонние JavaScript-пакеты не нужны.

При пустом `config.js` каждый логин открывает отдельное расписание в текущем браузере. Пароль не записывается. Данные шифруются AES-GCM, а ключ выводится из пароля через PBKDF2. После перезагрузки нужно войти снова. Очистка данных сайта удаляет локальные аккаунты, восстановление забытого пароля для них недоступно.

## GitHub Pages и афиша

В репозитории выбери **Settings → Pages → Source → GitHub Actions**. Workflow «Планер и обновление афиши» запускается после изменений в `main`, по расписанию дважды в сутки и вручную через **Actions → Run workflow**. Адрес сайта появится у задания `deploy`.

`sync_afisha.py` получает афишу Новошахтинского драматического театра за предыдущий, текущий и два следующих месяца. При сбое прямого запроса он пробует получить ту же публичную страницу через [AllOrigins](https://allorigins.win/). Если оба запроса не удались, публикация использует последние доступные данные. На GitHub расписание публичного репозитория может отключиться после 60 дней без активности. Его можно снова включить во вкладке **Actions**.

## Облачные аккаунты

Чтобы один аккаунт открывал те же события на телефоне и компьютере, подключи проект Supabase.

1. В SQL Editor выполни `supabase.sql`. Таблица и политики разрешают каждому вошедшему пользователю читать и изменять только свои события.
2. В Authentication включи вход по email и паролю и подтверждение email. В URL Configuration укажи адрес опубликованного планера в **Site URL** и разрешённых адресах перенаправления. Для отправки регистрационных писем обычным пользователям подключи [свой SMTP](https://supabase.com/docs/guides/auth/auth-smtp).
3. В `config.js` укажи URL проекта и публичный ключ `sb_publishable_…`. Ключи `service_role` и `sb_secret_…` предназначены для сервера и не должны попадать в этот репозиторий.
4. После публикации зарегистрируй аккаунт, используя email как логин, подтверди его и войди. Локальные аккаунты и события в облачный проект автоматически не переносятся.
